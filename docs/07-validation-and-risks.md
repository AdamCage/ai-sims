# Проверка качества и риски

Статус: предложенный подход к проверке. Реализация, тесты и запросы к платным моделям ещё не запускались.

## Два разных результата

**Корректность:** правила не нарушаются, предметы учитываются, зрение ограничено, старый запрос не меняет новую сцену, записанная история воспроизводится.

**Качество опыта:** персонажи различимы по поступкам, сведения меняют решения, давление среды порождает содержательные взаимодействия, зритель понимает причины и хочет продолжить наблюдение.

Первый результат можно проверять контролируемыми ситуациями. Второй требует автономных прогонов и оценки человеком. Технически корректная симуляция ещё может оказаться скучной.

## Что измерять

| Область | Наблюдение/метрика | Как интерпретировать |
| --- | --- | --- |
| Зрение | Соответствие кадра геометрии; распознавание видимых объектов; ошибки по категориям | Ошибку рендера, утечку контекста и ошибку VLM учитывать отдельно |
| Действия | Доля валидных и исполненных команд, причины отказов | Повторяющиеся отказы могут означать плохой интерфейс действий, а не плохой характер |
| Информация | Источники убеждений, путь сообщения, изменение действий после новой улики | Число сообщений само по себе не означает передачу полезных сведений |
| Память | Сохранность недавних данных, изменение старших слоёв, ошибки узнавания/источника, расходы консолидации | Сравнивать субъективную версию с закрытым trace; точное извлечение из dev-архива не является памятью |
| Артефакты | Добровольные записи/снимки, доступ к содержимому, судьба экземпляров, повторный просмотр | Точность содержимого и правильность его интерпретации измеряются раздельно |
| Распределение | Полученные пайки, очередь, фактические держатели, исполненные сделки | Права, принадлежность и перемещение проверяются отдельно |
| Связь | Созданные/доставленные/прочитанные версии, задержки и вмешательства | Полученная версия может отличаться от исходника; точный trace закрыт для персонажей |
| Внешность | Различимость изменяемых черт в first-person кадре, различия первых впечатлений и их пересмотр | Декларация в профиле не доказывает визуальное восприятие |
| Договорённости | Принятые, исполненные, нарушенные и неосуществимые обязательства | Нужна проверка фактического результата, а не наличия слова «обещаю» |
| Выживание | Расход, время в критическом состоянии, доступ к помощи, исход | Максимум выживших не обязательно означает интересный сценарий |
| Поведение | Доля разговоров без действий, повторения, различия между профилями | Высокая речевая активность может скрывать отсутствие решений |
| Техника | Время шага, очередь, p50/p95 задержки, таймауты, размер кадров и контекста | Сопоставлять с выбранным правилом времени и ожидания зрителя |
| Расходы | Запросы/кадры на игровой интервал, токены, фактически сообщённая стоимость | Не рассчитывать цену только по числу агентов; учитывать зрение и повторы |
| Интерес | Может ли зритель назвать мотив/причину, выбрать интересного героя и предсказать следующий конфликт? | Небольшая человеческая оценка полезнее автоматического «балла драмы» |

Пороговые значения выбираем после обсуждения ожиданий и первых замеров. Пока это список измерений, а не готовый договор приёмки.

## Протокол эксперимента

1. Сформулировать один вопрос: например, помогает ли зрительная проверка опровергнуть слух?
2. Зафиксировать карту, размещение, профили, доступные каналы, правила и версию наблюдений.
3. Проверить ситуацию ручными либо записанными действиями.
4. Запустить простую политику и целевой режим VLM на сопоставимых условиях.
5. Сохранить исходное состояние, кадры/их ссылки, ответы, действия, случайные результаты и вмешательства.
6. Сравнить исходы, причины ошибок, расходы и понятность эпизода; изменить один фактор.

При сравнении визуального восприятия контрольная политика может иметь структурированное наблюдение, но это преимущество должно быть явно отмечено. Для более честного сравнения выбора действий можно дать обеим политикам одинаковый результат распознавания. Диагностический контроль без VLM не является продуктовым вариантом.

Новый прогон с тем же seed и повторными вызовами VLM не равен replay. Альтернативная ветвь истории тоже является новым прогоном.

## Основные риски и проверки

| Риск | Как обнаружить | Возможная мера, требующая проверки |
| --- | --- | --- |
| Модель по умолчанию не принимает изображения | Проверить официальный каталог и минимальный запрос после настройки доступа | Зафиксировать несовместимость; согласовать другую VLM, не убирать требование зрения |
| Персонаж получает скрытые сведения через интерфейс | Проверить кадр, текст, подсказки действий, память и инструменты | Фильтровать все каналы; неизвестные объекты не перечислять |
| Слепота обходится инструментом телефона/фото/дневника | Проверить payload новых наблюдений и ответы инструментов | Нет текущих пикселей и зрительного содержимого; незрительные каналы разрешаются отдельно |
| Травма остаётся только описанием | Сравнить скорость, расход сил и допустимые команды | Физические эффекты исполняются правилами тела, проверяются повторно после ожидания VLM |
| Всеведение наблюдателя утекает в опыт участников | Открывать полную карту, роли и память всех при активной симуляции | Панели игрока изолированы от кадров/контекстов; просмотр не является вмешательством |
| Стартовый prompt сообщает устройство неизвестного места | Проверить исходные запросы, имена ролей, описание сценария и оставшийся контекст | Отдельно инициализировать мир и личные знания; очищать выбранную память без неявного удаления навыков |
| Изображение слишком сложное для выбранной VLM | Проверить маленькие сцены с поворотом, окклюзией и похожими предметами | Упростить представление и размеры объектов; проверить разрешение |
| Забывание обходится скрытым доступом к артефакту | Проверить контекст после потери фотографии/дневника | Изображение и текст повторно доступны только через допустимый доступ; память о них стареет отдельно |
| Агент памяти «исправляет» прошлое по истине мира | Проверить его входы, retrieval и технические метаданные в контексте | Только личные данные; закрытый trace не используется для исправления субъективных ошибок |
| Любая порча суммаризатора оправдывается субъективностью | Отделить допустимые ложные детали от потери свежих данных, чужого владельца, неверных ссылок | Проверять контракт и версию; измерять характер и скорость искажений |
| Уничтожение фото стирает все свидетельства | Проверить показ, копирование, потерю и уничтожение отдельных экземпляров | Раздельные объекты и память свидетелей; dev-архив не участвует в игре |
| Контроль сети незаметно даёт всеведение | Проверить права на каждый сервис, локальный файл и технический trace | Раздельные полномочия; только доступная наблюдателю часть журнала |
| Подмена переписывает прошлый опыт читателя | Сохранить исходное прочтение, затем изменить серверную версию | Старый недавний опыт неизменен; повторное открытие — новое наблюдение |
| Продажа телефона переносит все права/знания | Передать заблокированное и разблокированное устройство с файлами | Различать предмет, аккаунт, текущий доступ и личную память |
| Пайки и сеть дают неограниченные ресурсы | Одновременные запросы, повтор выдачи и поддельное уведомление | Авторитетный учёт и явная граница полномочий, согласуемая для сценария |
| Крыша скрывается сразу для всех камер | Сравнить отправляемый кадр с верхним видом | Разделить зрительские и агентские render layers, не менять общую геометрию |
| Навигация знает тайные маршруты | Задать цель за неизученным коридором | Ограничить доступные цели и пути знаниями персонажа |
| Персонажи только разговаривают | Проверить исполненные действия и расход времени | Явное завершение беседы, цена времени, исполнимые предложения |
| Отношения существуют только в тексте | Сравнить выбор после помощи/нарушения | Личные записи поступков и компактные параметры отношений |
| Агрессивный дефицит обрывает историю | Группа не успевает исследовать/договориться | Подобрать темп потребностей и доступный путь помощи |
| Время сети решает, кто выжил | Сопоставить задержку ответа и исход | Определить семантику ожидания, порядок намерений и резервирование |
| Ошибочный ответ или изображение ломают ход | Внедрить timeout, неверный JSON, неподдерживаемый image input | Ограниченные повторы, определённый fallback действия, явная диагностика |
| Платформенная работа разрастается | Долгая разработка инфраструктуры до первой ситуации | Один сценарий и минимальные адаптеры до обобщения |
| Красивый дайджест скрывает неработающие правила | Сверить пересказ с событиями | Пересказывать только записанные последствия; сохранять ссылки на события |

## Контрольные точки

- **G0 — замысел:** согласованы вмешательства, ставки и первая ситуация.
- **G1 — зрение и API:** согласованы перспектива/поле зрения; проверена совместимость выбранной VLM с изображениями.
- **G2 — устройство демки:** выбран вариант ядра и визуализации по маленькому техническому эксперименту.
- **G3 — корректность:** проходят согласованные проверки зрения, ресурсов, времени и replay.
- **G4 — поведение:** три опоры работают вместе, результаты и проблемы показаны автору.
- **G5 — следующий масштаб:** автор решает, расширять ли механику, улучшать ли представление или увеличивать группу.

Это предлагаемые точки обсуждения, без оценки сроков. Сейчас выполнена подготовка документации; ни одна техническая контрольная точка не считается пройденной.

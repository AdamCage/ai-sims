# Зрение персонажей и VLM

Обновлено: 2 ноября 2026. Поле зрения и реальное зрительное восприятие при сохранном зрении, а также использование VLM обязательны по требованию автора. Персонаж может быть или стать слепым; эта особенность отключает его текущий зрительный канал.

## Подтверждённая модель по умолчанию

Провайдер: **RouterAI**. API base URL: `https://routerai.ru/api/v1`. После уточнения автор выбрал опубликованный latest-алиас:

```text
~deepseek/deepseek-v4-flash-latest
```

Изначально автор назвал `deepseek-v4.1-flash-latest`. Такого точного идентификатора не обнаружено в публичном каталоге; он сохранён здесь как история уточнения, а не активная настройка. Автору были предложены опубликованные варианты, и он явно выбрал alias выше.

На дату проверки публичный каталог заявляет для alias входы `text,image` и текстовый выход. Официальная страница alias указывает на `deepseek/deepseek-v4.1-flash-1017`. Это подтверждение заявленной модальности, а не проверка качества зрения, задержки или цены реальным вызовом. [Каталог](https://routerai.ru/api/v1/models), [страница alias](https://routerai.ru/models/~deepseek/deepseek-v4-flash-latest).

Alias может изменяться. Предложение: сохранять в каждом запуске запрошенный alias, модель из ответа провайдера, время и снимок доступных метаданных. Если провайдер не раскрывает точную ревизию, записывать это явно. Для сравнения новых прогонов позднее можно отдельно согласовать закреплённую ревизию; сейчас default остаётся выбранным автором latest.

## Что значит «видеть»

У каждого зрячего агента есть собственный зрительный кадр. Он построен из состояния мира, положения и направления взгляда персонажа. Предмет за стеной не виден; предмет позади не должен появляться в текущем кадре; изменение взгляда или открытие двери изменяет доступное изображение.

При слепоте текущие пиксели мира и раскрывающие сцену текстовые подписи не передаются. Модель остаётся той же VLM и получает доступный незрительный контекст. Нельзя выдавать содержимое фото/экрана/дневника через инструмент чтения как обход слепоты. Наблюдатель по-прежнему видит всю игровую информацию. Предлагается сохранять ранее полученные визуальные воспоминания как прошлый опыт; новые кадры не добавляются. См. [тело и возможности](16-body-and-capabilities.md).

VLM интерпретирует пиксели и может ошибаться. Геометрическая доступность и распознавание — разные этапы. Система не должна молча исправлять ошибки восприятия, подставляя полный объективный список предметов.

Выход объекта из текущего поля зрения не стирает память о нём. Нужно различать «сейчас не видит», «раньше видел», «слышал от другого» и «не знает о существовании».

Допустимы дополнительные сведения, которые персонаж действительно имеет: собственное самочувствие, инвентарь, память, услышанная речь, результат своей попытки. Для каждого поля нужно указать источник. Инвентарь закрытого чужого контейнера не становится известным только потому, что объект есть в базе мира.

Наблюдателю доступна вся игровая информация, включая скрытые объекты и исходники подменённой переписки. Его панели и способы обзора не являются каналом восприятия персонажа. Начальное знание о месте, других участниках и ролях задаётся сценарием; первая камера даёт новый опыт, а не полный брифинг об условиях. См. [старт и наблюдателя](14-scenario-start-and-observer.md).

## Параметры зрения — предложение структуры

| Параметр | Для чего | Статус |
| --- | --- | --- |
| Положение и ориентация | Откуда и в какую сторону смотрит персонаж | Обязательны по смыслу зрения |
| Угол поля зрения | Граница направления доступного изображения | Число не выбрано |
| Дальность | Ограничение видимости по расстоянию | Значение и геометрия не выбраны |
| Преграды | Стены, двери, непрозрачные объекты | Конкретные правила открыты |
| Перспектива | Рабочее предложение автора: 3D из глаз, зрителю — вид сверху под углом | Рекомендовано к подтверждению; проекция зрителя ещё открыта |
| Поворот | Изменение направления взгляда телом/головой | Действие и стоимость открыты |
| Освещение | Видимость в темноте и при отключении света | Кандидат после базовой геометрии |
| Размер кадра | Читаемость предметов, стоимость передачи и модели | Подобрать экспериментом |
| Частота кадров для решений | Когда запрашивать новую интерпретацию | Не равна автоматически частоте анимации |

Для предложенного 3D-вида нужно явно определить вертикальный/горизонтальный FOV и aspect ratio, а также направление взгляда по высоте. Вид зрителя 2.5D не заменяет изображение из глаз персонажа. Если вернуться к альтернативному виду агента сверху, сектор должен маскировать закрытые и недоступные области. См. [устройство пространства и камер](09-world-and-appearance.md).

## Предлагаемый конвейер

1. Зафиксировать состояние мира и позу персонажа для конкретного момента.
2. Построить его вид с учётом границ и преград.
3. Исключить интерфейс зрителя, отладочные подписи, скрытые комнаты и служебные данные.
4. Получить байты изображения и связать их с `run_id`, `agent_id`, `tick`, параметрами камеры и hash.
5. Добавить только разрешённый текстовый контекст и словарь команд.
6. Отправить индивидуальный multimodal-запрос и проверить ответ как намерение.
7. Сохранить отправленный кадр, контекст, ответ и результат исполнения.

Предложение: один мир и несколько видов, а не отдельный процесс движка на каждого персонажа. При одном кадре и одном решении каждого из семи агентов за раунд получаем семь разных изображений и до семи запросов. Это пример нагрузки, не выбранная частота. Коллаж всех семи видов нельзя отправлять каждому агенту: он раскроет чужую информацию.

**Открытый вопрос: как указать цель действия на изображении?** Возможны координаты, направление либо видимые метки объектов. Нужно проверить точность сопоставления пикселей и команды без выдачи полного списка объектов мира. Служебный ID не должен раскрывать неизвестный предмет; попытка взаимодействия всё равно проверяется правилами по актуальному состоянию.

## API изображений: проверенные сведения

Официальный гайд RouterAI описывает `POST /api/v1/chat/completions`: в `messages[].content` передаются блок текста и `image_url`. Изображение может быть публичным HTTPS URL либо `data:image/png;base64,...`; перечислены PNG, JPEG, WebP и GIF. Для кадров локальной сцены подходит документированный base64-формат. [Гайд по изображениям](https://routerai.ru/docs/guides/overview/multimodal/images).

Это описание интерфейса, не созданная конфигурация приложения. Ключ не запрашивался, генерация не выполнялась, фактическая стоимость не измерялась. Численные лимиты изображений для выбранного alias не установлены проверенными источниками; `per_request_limits: null` в каталоге не означает отсутствия лимитов. Поддержку требуемого формата команд и стабильность структурированного ответа предстоит проверить.

## Память о зрении

Автор уточнил последовательность: недавний неизменный контекст → субъективные эпизоды → всё более краткие старые версии, с возможным накоплением ошибок. Это автоматически выполняет отдельный агент памяти. Дневник и точное фото создаются добровольными действиями и сохраняются отдельно. См. [память](10-memory-and-notes.md) и [артефакты](11-diary-and-photographs.md). Интервалы, бюджеты и форма носителей открыты.

Описание, сформированное агентом памяти, может быть ошибочным и предвзятым. Поздний кадр или просмотр фото даёт новый материал для интерпретации, сохраняя настоящее происхождение в закрытом trace. Субъективная память может путать источник, но это не превращает чужое сообщение в реальное зрительное событие прошлого.

## Минимальная проверка до сложных социальных сцен

- Видимый объект распознаётся в простой сцене.
- Объект за спиной исчезает из текущего кадра и появляется после поворота.
- Стена и закрытая дверь перекрывают изображение; открытие двери меняет его.
- Два персонажа из разных точек получают разные наблюдения.
- Ни кадр, ни текст, ни список команд не раскрывают скрытый предмет.
- Неверное распознавание отличимо от технической ошибки рендера или отказа API.

После проверки простого зрения добавлять мелкие детали, текст записок, плохое освещение и неоднозначные сцены. Их читаемость для выбранной VLM нельзя считать гарантированной.

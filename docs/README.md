# Документация игры и лаборатории механик

Обновлено: 2 ноября 2026. Стадия: исследование и совместное проектирование, до реализации.

Это рабочая документация для диалога с автором. Она отделяет исходный замысел, принятые решения, предложения команды и проверяемые гипотезы. Подробность описания сама по себе не означает, что решение принято.

## Что уже определено

- Первая цель — демка механик, «уровень разработчиков», с небольшим числом персонажей, ориентир — до 7.
- Основной опыт будущей игры — наблюдать за автономными персонажами и иногда менять условия. Подтверждено автором в текущем диалоге.
- Демка должна совместно проверить отношения и договорённости, ограниченную информацию и выживание при дефиците. Автор выбрал все три направления.
- Сейчас создаём документацию и обсуждаем решения. Реализация игры и окончательный выбор движка ещё не согласованы.
- Упомянутые проекты добавлены в `.example` для изучения и поиска подходящих подходов. Ни один не выбран основой продукта.
- Зрячий персонаж видит мир через собственное поле зрения и VLM; слепота отключает текущий зрительный канал. Default модели: RouterAI, `~deepseek/deepseek-v4-flash-latest`.
- У персонажей обязательна кастомизируемая внешность, участвующая в субъективном восприятии и отношениях. Глубина редактора пока не выбрана.
- Автоматическую субъективную память формирует отдельный агент: недавний контекст неизменен, старые слои сокращаются и могут накапливать ошибки.
- В проработку введены добровольный краткий дневник и фотография как точное изображение момента и самостоятельный артефакт для социальных действий.
- Фотографии бывают физическими и цифровыми по сценарию. Камеры/телефоны — предметы, доступные через мир и обмен, не обязательно с начала.
- Ошибки памяти возникают только при субъективном сокращении; специальное добавление ложных деталей исключено.
- Для первой демки автор выбрал автоматический терминал пайков/очереди и контроль сети вплоть до удаления и подмены сообщений.
- Игроку-наблюдателю доступна вся информация о мире и всех персонажах. Ограничения знания действуют для персонажей, а не для игрока.
- Стартовая осведомлённость, сохранённые воспоминания и раскрытие ролей задаются сценарием. В неизвестном старте сведения об условиях не выдаются автоматически.
- Характер — устойчивая личностная часть системного prompt с неизменным фундаментом. Возможности пересмотра возникают с интервалами 1–60 игровых дней, в среднем 30 в обычных условиях. При суммаризации агент памяти решает по опыту, менять ли вторичные черты; характер может сохраняться и дольше 60 дней.
- В демке есть общее состояние и части тела. Одной здоровой рукой доступны подходящие действия; обе сломанные блокируют ручные действия и атаку. Повреждение ноги даёт боль/замедление/усталость, две сломанные ноги — только ползание, все четыре сломанные конечности — отсутствие самостоятельного перемещения. Слепота запрещает видеть/читать/писать.

Рабочее предложение пространства: объёмный мир, вид зрителя сверху под углом, ходьба по поверхностям этажей и 3D-вид из глаз персонажа. Для памяти уточняются интервалы каскадного сокращения; для артефактов — доступ и копирование; для сети и выдачи — носители полномочий. Сообщения, форум, голосования, игры и подобие интернета заданы направлениями телефонных услуг; объём приложений первой сборки ещё обсуждается.

## Как работаем

1. Обсуждаем по одному вопросу из [повестки](15-discussion-agenda.md), при необходимости несколько сообщений на тему.
2. Записываем ответ автора и его последствия в журнал решений.
3. Обновляем затронутые документы; спорные варианты остаются помеченными.
4. После согласования границ демки готовим короткий технический эксперимент для выбора архитектуры.
5. К реализации переходим после явного решения автора.

Предложения команды можно оспаривать и менять. Для отменённого решения сохраняем причину изменения. При конфликте формулировок актуальное решение автора в [журнале](06-decisions-and-questions.md) имеет приоритет; остальные документы приводим в соответствие.

## Статусы

- **Подтверждено** — прямо следует из запроса автора или его ответа; источник указан.
- **Предложение** — рекомендуемый вариант для обсуждения.
- **Гипотеза** — ожидаемый эффект, который ещё нужно проверить.
- **Открыто** — решение не принято, варианты остаются допустимыми.
- **Проверено по исходнику** — факт о конкретной версии внешнего проекта; не доказательство качества нашей игры.
